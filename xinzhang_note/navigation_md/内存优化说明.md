# ORION 训练内存优化说明

## 问题分析

错误信息：
```
RuntimeError: [enforce fail at alloc_cpu.cpp:117] err == 0. 
DefaultCPUAllocator: can't allocate memory: you tried to allocate 2097152 bytes. 
Error code 12 (Cannot allocate memory)
```

## 深度学习训练的内存使用

### CPU 内存（RAM）用途：
1. **数据加载**：图像解码、数据增强、批次准备
2. **模型初始化**：创建模型结构、权重张量
3. **优化器状态**：Adam/AdamW 需要存储动量和二阶矩
4. **中间缓存**：DataLoader 的预取缓存
5. **梯度累积**：backward 过程中的临时变量

### GPU 显存（VRAM）用途：
1. **模型参数**：权重、偏置
2. **激活值**：前向传播的中间层输出
3. **梯度**：反向传播计算的梯度
4. **优化器缓存**：GPU 上的优化器状态

## 典型内存需求

ORION 模型（调试配置）：
- **CPU 内存**：约 16-24GB
  - 数据加载：~8GB
  - 模型初始化：~4GB
  - 优化器：~6GB
  - 其他开销：~4GB

- **GPU 显存**：约 12-16GB
  - 模型参数：~6GB
  - 激活值：~4GB
  - 梯度：~3GB
  - 其他：~3GB

## 优化措施

### 1. 脚本级优化（`orion_debug.sh`）

✅ **已实现：**
- 移除内存硬限制（`ulimit -v` 太严格）
- 优化 GPU 显存分配策略
- 限制多线程数量（OMP, MKL）
- 添加内存监控
- 降低进程优先级（nice）
- 设置超时保护（10分钟）

### 2. 配置级优化（`orion_debug.py`）

✅ **已实现：**
- 启用梯度检查点（`with_cp=True`）：节省 30-50% 显存
- 冻结 backbone（`freeze_backbone=True`）：减少梯度内存
- 单进程数据加载（`workers_per_gpu=0`）：避免多进程开销
- 最小 batch size（`batch_size=1`）
- 最少迭代次数（`num_iters_per_epoch=5`）

### 3. 运行前建议

**检查系统资源：**
```bash
# 检查可用内存
free -h

# 检查GPU显存
nvidia-smi

# 清理不必要的进程
# 关闭浏览器、IDE 等占用大量内存的程序
```

**清理系统缓存：**
```bash
# 清理页面缓存
sudo sync
sudo sh -c 'echo 3 > /proc/sys/vm/drop_caches'
```

**监控资源：**
```bash
# 实时监控内存
watch -n 1 free -h

# 实时监控GPU
watch -n 1 nvidia-smi
```

## 如果仍然内存不足

### 方案 A：进一步减少模型复杂度
```python
# 在配置文件中：
num_iters_per_epoch = 1  # 只运行1个iter用于测试流程
predict_modes = 3  # 减少预测模式
```

### 方案 B：使用更小的模型
考虑使用轻量级配置：
- 减少 transformer 层数
- 减少注意力头数
- 使用更小的 embedding 维度

### 方案 C：使用更强大的硬件
推荐配置：
- **最低要求**：32GB RAM + 16GB VRAM
- **推荐配置**：64GB RAM + 24GB VRAM（如 RTX 3090/4090）
- **理想配置**：128GB RAM + 40GB VRAM（如 A100）

## 故障排查

### 错误：Cannot allocate memory
- **原因**：系统内存不足
- **解决**：关闭其他程序，增加 swap 空间

### 错误：CUDA out of memory
- **原因**：GPU 显存不足
- **解决**：启用梯度检查点，减少 batch size

### 系统死机
- **原因**：OOM killer 或内存压力过大
- **解决**：使用脚本的超时和监控机制，不要使用 `sudo` 运行
