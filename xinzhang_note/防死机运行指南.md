# ORION 防死机运行指南

## 🚨 问题总结

**现象：** 运行训练时系统死机

**根本原因：**
1. **CPU 内存不足**：深度学习训练同时需要大量 CPU 内存和 GPU 显存
2. **内存压力过大**：数据加载、模型初始化、优化器状态都占用内存
3. **无保护机制**：之前的脚本缺乏内存监控和自动终止

**CPU内存用途：**
- 数据加载和预处理：~8-12GB
- 模型初始化：~4-6GB  
- 优化器状态：~4-6GB
- 系统和其他进程：~4-8GB
- **总计：约 20-32GB**

## ✅ 已实施的保护措施

### 1. **多层内存监控**

#### Bash 层监控（每5秒）
- ✅ 实时检查内存使用率
- ✅ 内存超过 80% → 发出警告
- ✅ 内存超过 90% → **自动终止训练**
- ✅ 可用内存 < 1GB → **自动终止训练**

#### Python 层监控（备用）
- 可选的 Python 包装器进行双重保护

### 2. **日志优化**

**控制台输出：** 只显示关键信息
- 错误、警告、异常
- 训练进度（Epoch, iter, loss）
- 状态变化

**详细日志文件：**
- `full_output.log` - 完整训练输出
- `summary.log` - 关键信息摘要
- `resource_monitor.log` - 资源使用详情（每5秒）
- `warnings.log` - 所有警告信息
- `final_system_state.log` - 退出时的系统状态快照

### 3. **资源限制**

```bash
# GPU 显存优化
PYTORCH_CUDA_ALLOC_CONF=max_split_size_mb:64,expandable_segments:True

# CPU 内存优化
MALLOC_TRIM_THRESHOLD_=100000  # 积极释放内存

# 多线程限制
OMP_NUM_THREADS=2
MKL_NUM_THREADS=2
```

### 4. **配置优化**

```python
# 启用梯度检查点（节省30-50%显存）
with_cp=True

# 最小资源配置
batch_size=1
workers_per_gpu=0  # 单进程加载
num_iters_per_epoch=2  # 只运行2个iter测试
```

### 5. **超时保护**

- 10分钟超时自动终止
- 防止训练无限运行

### 6. **进程清理**

- 脚本退出时自动清理所有子进程
- 清理残留的 GPU 进程
- 保存系统状态快照

## 🔍 故障排查

### 问题 1: 仍然死机

**原因：** 系统内存真的不够

**解决方案：**

1. **增加 Swap 空间**
```bash
sudo fallocate -l 16G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
# 查看是否生效
free -h
```

2. **关闭更多程序**
```bash
# 查看内存占用
ps aux --sort=-%mem | head -n 20

# 关闭浏览器、IDE等
```

3. **降低监控阈值**（脚本中修改）
```bash
# 在 monitor_resources 函数中
if [ "$mem_percent" -gt 75 ]; then  # 从90改为75
```

### 问题 2: 训练立即被终止

**原因：** 初始内存就已经很高

**检查：**
```bash
free -h  # 查看可用内存
```

**解决：**
- 先运行 `prepare_system.sh` 清理内存
- 重启电脑
- 确保至少有 16GB 可用内存

### 问题 3: 没有日志文件

**原因：** 训练太早被终止，或权限问题

**检查：**
```bash
ls -lah /tmp/orion_debug_*/
```

**解决：**
- 确保 /tmp 有写入权限
- 检查磁盘空间：`df -h /tmp`

### 问题 4: 内存分配错误

```
Error code 12 (Cannot allocate memory)
```

**原因：** 系统内存不足或限制过严

**解决：**
1. 检查是否设置了 `ulimit`
```bash
ulimit -a | grep memory
```

2. 确保脚本中没有设置严格的内存限制

3. 增加系统内存或swap

## 🎯 优先级建议

如果系统资源有限，按以下优先级操作：

### 优先级 1: 必须做
1. ✅ 运行 `prepare_system.sh` 清理内存
2. ✅ 关闭浏览器、IDE等大内存程序
3. ✅ 确保至少 16GB 可用内存
4. ✅ 使用普通权限运行（不用sudo）

### 优先级 2: 强烈推荐
1. ✅ 增加 Swap 空间到 16GB
2. ✅ 重启电脑清理内存
3. ✅ 监控资源使用

### 优先级 3: 如果还不行
1. 降低监控阈值（75% vs 90%）
2. 减少迭代次数到 1
3. 考虑使用更强的硬件
4. 分阶段测试（先只测试数据加载，再测试模型初始化）


- 起始内存就很高（85%）

- 自动终止避免死机

**解决：**
- 清理更多内存后再运行
- 增加 Swap 空间

1. **立即按 Ctrl+C** 终止

```bash

nvidia-smi | grep python | awk '{print $5}' | xargs -r kill -9
```

3. 重启电脑清理状态
