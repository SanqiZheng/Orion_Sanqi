# ORION 常见问题排查

## ❌ 问题1: KeyError: 'NuScenesDataset is not in the dataset registry'

### 错误信息
```
KeyError: 'NuScenesDataset is not in the dataset registry'
```

### 原因分析
1. **根本原因**: 使用了**训练配置文件**进行推理，但该配置缺少 `data.test` 配置
2. **错误流程**:
   ```
   test.py 读取配置 → 查找 cfg.data.test
   → 配置中没有 data.test
   → 回退到基础配置（_base_）
   → 基础配置中使用 NuScenesDataset
   → 该数据集类未注册 → 报错
   ```

3. **为什么会这样**:
   - 训练配置（`orion_stage1_train_minimal.py`）继承自基础配置
   - 基础配置中定义了 `data.test = NuScenesDataset`
   - 训练时只需要 `data.train` 和 `data.val`
   - 推理时需要 `data.test`，但训练配置中没有覆盖它

### ✅ 解决方案

**方案1: 使用修复后的配置（已修复）**

已在 `orion_stage1_train_minimal.py` 中添加了 `data.test` 配置：

```python
data = dict(
    # ... train 和 val 配置 ...
    
    # 🔥 新增：test配置（用于推理）
    test=dict(
        type='B2DOrionDataset',  # 使用正确的数据集类
        data_root=data_root,
        ann_file=ann_file_val,   # 使用验证集数据
        test_mode=True,
        # ... 其他配置 ...
    ),
)
```

**方案2: 使用专门的推理配置**

如果需要LLM和VQA功能，使用：
```bash
bash adzoo/orion/orion_dist_eval_llm.sh \
    adzoo/orion/configs/orion_stage3_infer_llm_vqa_light.py \
    ckpts/eva02_petr_proj.pth \
    1
```

## ❌ 问题2: CUDA out of memory（显存不足）

### 错误信息
```
RuntimeError: CUDA out of memory. Tried to allocate XXX MiB
```

### 原因分析
- 模型或数据占用的显存超过GPU容量
- 常见原因：batch_size太大、图像分辨率太高、模型层数太深

### ✅ 解决方案

**方案1: 使用轻量配置**
```bash
# 使用不带LLM的配置（降低7-8GB显存）

    adzoo/orion/configs/orion_stage1_train_minimal.py \
    ckpts/model.pth \
    1
```

**方案2: 修改配置降低资源占用**

在配置文件中修改：
```python
# 1. 减少查询数量
pts_bbox_head = dict(
    num_query=300,       # 从600减半
    topk_proposals=150,  # 从300减半
)

# 2. 降低图像分辨率
ida_aug_conf = {
    "final_dim": (160, 320),  # 从(320, 640)减半
}

fp16 = dict(loss_scale='dynamic')
```

**方案3: 清理GPU显存**

## ❌ 问题7: KeyError: 'all_traj_preds'（bbox_coder类型不匹配）

### 错误信息
```python
KeyError: 'all_traj_preds'
# 在 fut_nms_free_coder.py:120
all_traj_preds = preds_dicts['all_traj_preds'][-1]
```

### 原因分析

**根本原因**: bbox_coder类型配置错误

- 原始推理配置使用 `CustomNMSFreeCoder`
- 这个coder期望模型输出包含 `all_traj_preds`（轨迹预测）
- 但预训练权重可能不包含轨迹预测模块
- 导致字典中缺少该键

### ✅ 解决方案（已修复）

**修改bbox_coder类型**，使用与训练配置一致的 `NMSFreeCoder`：

```python
# 修改前（错误）
bbox_coder=dict(
    type='CustomNMSFreeCoder',  # ❌ 期望轨迹预测
    ...
)

# 修改后（正确）
bbox_coder=dict(
    type='NMSFreeCoder',  # ✅ 与训练配置一致
    ...
)
```

已修复的文件：
- `configs/orion_stage3_infer_light.py` ✅
- `configs/orion_stage3_infer_llm_vqa_light.py` ✅

### 物理意义说明

**NMSFreeCoder vs CustomNMSFreeCoder**:

1. **NMSFreeCoder** (基础版):
   - 处理基本的3D检测输出
   - 包含：边界框位置、尺寸、方向、类别
   - 不需要轨迹预测

2. **CustomNMSFreeCoder** (增强版):
   - 除了基础检测输出外
   - 还需要：`all_traj_preds`（未来轨迹预测）
   - 用于端到端自动驾驶（规划功能）

**为什么预训练权重不包含轨迹预测**:
- Stage1预训练只训练检测和地图
- 轨迹预测在Stage2/3才加入
- 所以使用Stage1权重时，要用基础版coder

## ❌ 问题8: LLM加载后显存不足（CUDA OOM）

### 错误信息
```
torch.OutOfMemoryError: CUDA out of memory. 
Including non-PyTorch memory, this process has 13.63 GiB memory in use.
```

### 原因分析

**实测数据**（RTX 4060 Ti 16GB）:
- LLM模型（FP16）占用: 13.6GB
- 剩余显存: 仅0.13GB
- 还需要加载: EVA骨干网络(2-3GB) + 检测头(1-2GB) + 缓存(1-2GB)
- **总需求**: 18-20GB显存 > 16GB可用 ❌

### ✅ 解决方案

**方案1: 使用不带LLM的配置（推荐）**✅

```bash
bash adzoo/orion/orion_dist_eval_llm.sh \
    adzoo/orion/configs/orion_stage3_infer_light.py \
    ckpts/eva02_petr_proj.pth \
    1
```

实测成功：
- 显存占用: ~8GB
- 推理速度: ~1秒/样本
- 包含完整的检测、地图、运动预测功能

**方案2: 升级GPU硬件**

需要更大显存的GPU：
- RTX 4090 24GB ✅
- RTX A6000 48GB ✅  
- V100 32GB ✅

**方案3: 使用量化LLM（需要代码修改，未实现）**

理论上可以：
- 8-bit量化: 降到7-8GB
- 4-bit量化: 降到4-5GB
- 但需要修改 `load_model()` 函数支持量化

### 物理意义说明

**为什么LLM这么大**：
- 7B参数的LLaMA模型
- FP16: 每个参数2字节 → 7B × 2 = 14GB
- FP32: 每个参数4字节 → 7B × 4 = 28GB

**为什么无法容纳在16GB显存**：
- LLM本身: 13.6GB
- EVA-ViT骨干: 2-3GB（1024维 × 24层）
- 检测+地图头: 1-2GB
- 中间激活: 1-2GB
- **总计**: 18-20GB
